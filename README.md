# Car detailing site template

A one-page car detailing website built to convert: packages priced by vehicle size, a before/after slider, and a multi-step booking request with a running estimate. Next.js, no CMS, no external image hosting.

The repo ships as a **concept build** for a fictional business, *Still Water Mobile Detailing* in *Cedar Bend, TX*. Every price, review, person and image is a labeled sample. The page says so in the footer and in the persistent concept tag, and it is `noindex`.

## Where everything lives

| What | Where |
|---|---|
| All business content: name, town, phone, packages, prices, add-ons, policies, hours, reviews, FAQs, before/after pairs, headlines | `config/business.ts` |
| Type of that config, with comments on each field | `types/site.ts` |
| Original photos you drop in | `assets/source/` |
| Generated WebP sizes and the width/height manifest | `public/images/` (run `npm run images`) |
| Page sections, each commented with the objection-map rows it answers | `components/Site.tsx` |
| Booking request form (3 steps, estimate, demo confirmation) | `components/BookingForm.tsx` |
| Before/after slider (touch, keyboard, screen reader) | `components/BeforeAfterSlider.tsx` |
| Price maths | `lib/pricing.ts` |
| Event tracking (Microsoft Clarity when an id is set) | `lib/tracking.ts` |

Components should not need edits between clients. If a difference can be handled in config, handle it in config.

## Run it

```bash
npm ci
npm run dev        # http://localhost:3000
npm run build      # production build, also what CI runs
```

## Images

No hotlinking. Put originals in `assets/source/` (jpg, png, webp or svg) and run:

```bash
npm run images
```

Each file becomes `public/images/<name>-{480,960,1600}.webp` plus an entry in `manifest.json` with its natural size, so every image on the page gets `width`, `height` and a `srcset`. Reference images in config by basename only, for example `before: "pair-interior-before"`.

Before/after pairs: name them `<thing>-before` and `<thing>-after`, add the pair to `beforeAfter` in config, and point a package's `proofPairId` at it. Shoot both photos from the same spot in the same light.

The sample art is generated by `npm run sample-art`. Delete those SVGs once real photos are in.

## Booking form

The form is a **request**, not a booking. The button says "Request a booking" and the copy beside it states the deposit, the cancellation policy and when the owner will text back. All of that comes from `config.booking`.

- `mode: "concept"`: nothing is sent; the confirmation screen says it is a demo.
- `mode: "client"`: wire `submit()` in `BookingForm.tsx` to the owner's inbox (a form endpoint, email API or CRM). Until then it falls back to opening a pre-filled text message.

Package buttons on the cards carry the package into the form. `?package=<id>` in the URL does the same, for ads or links.

## Tracking

Set `clarityProjectId` in config to enable Microsoft Clarity. Events: `booking_request_submit` (with package), `call_tap`, `text_tap`, `package_select`, `slider_interaction`. Traffic source comes from `utm_source` or the referrer and is set as a Clarity tag. With no id, events are no-ops (logged to the console in development).

## Making a client site

1. Clone the repo. Set `mode: "client"` in `config/business.ts`.
2. Replace every value in the config with facts the owner confirmed. Remove anything they can't confirm; a blank hides its section. Never invent prices, reviews, ratings or credentials, and never write "award-winning".
3. Drop their photos into `assets/source/` and run `npm run images`. No stock photos presented as their work.
4. Wire the form submit to their inbox and test it end to end.
5. Set `robots` to index in `app/layout.tsx` (it follows `mode`), add `metadataBase` with the real domain, and add LocalBusiness structured data only with confirmed facts.
6. Check it at 375px: no sideways scroll, thumb-sized buttons, the first screen shows what, where, and one button.

## Honesty rules

The objection map in the build prompt assumes what customers worry about. Each section in `components/Site.tsx` names the rows it answers in a comment so the owner or a real customer can confirm them. Protection claims (wax, sealant) use plain durations and should match the product's stated figures.
